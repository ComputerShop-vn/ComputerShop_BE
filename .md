Act as an expert backend developer. I need to build a comprehensive Warranty Management feature using a strict 3-Layer Architecture (Controller, Service, Repository) in Java and Spring Boot.

Requirements:

1. Entities & Enums (Database Design):

Warranty Entity (The Entitlement): This tracks the validity of the warranty. It must link directly to order_item_id (not just product_id) to accurately track specific purchased items.

Fields: id, order_item_id, serial_number (String), start_date, end_date, status, type, description.

Enums: WarrantyStatus (ACTIVE, EXPIRED, VOIDED), WarrantyType (MANUFACTURER, SELLER).

WarrantyClaim Entity (The History/Ticket): This tracks every time a customer brings an item in for service. It has a Many-to-One relationship with Warranty.

Fields: id, warranty_id, claim_date, customer_note (the issue reported), technician_note (how it was fixed), status, solution_type, return_date.

Enums: ClaimStatus (PENDING, PROCESSING, COMPLETED, REJECTED), SolutionType (REPAIR, REPLACE, REFUND).

2. Business Logic (Service Layer & Event Handling):

Auto-creation upon Order Completion: Create a Service method or a Spring Event Listener that triggers when an Order status becomes COMPLETED. It must iterate through the Order Items and automatically create a Warranty record for each valid item.

Date Calculation: Automatically calculate end_date = start_date + warranty months of the product.

Claim Processing Logic: Create service methods to open a new WarrantyClaim (system must check if the linked Warranty is still ACTIVE before accepting), update claim status, and add technician notes.

3. APIs (Controller Layer):

Create RESTful endpoints to manage this workflow (e.g., Get warranties by Order, Get claim history by Warranty ID, Create a new claim, Update claim status/technician notes).

Crucial Rule: You must use DTOs (Data Transfer Objects) for all Requests and Responses. Do not expose the Database Entities directly to the client.
